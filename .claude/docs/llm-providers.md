# 모델 제공자

어느 모델을 무엇에 쓰는가. 구현은 `app/llm/` 다.

제약은 `.claude/rules/llm.md` 에 있다. 여기서는 그 제약이 코드에서 어떤 모양인지를 적는다.

## 제공자가 다섯이다

| 이름 | SDK | 키 설정 | 모델 설정 |
|---|---|---|---|
| `gemini` | `google-genai` | `GEMINI_API_KEY` | `GEMINI_MODEL` |
| `claude` | `anthropic` | `CLAUDE_API_KEY` | `CLAUDE_MODEL` |
| `gpt` | `openai` | `GPT_API_KEY` | `GPT_MODEL` |
| `qwen` | `openai` | `QWEN_API_KEY` | `QWEN_MODEL` |
| `ollama` | `openai` | `OLLAMA_API_KEY` | `OLLAMA_MODEL` |

뒤의 셋은 OpenAI 호환 엔드포인트로 부른다. Qwen 과 Ollama Cloud 는 `*_BASE_URL` 로 주소를
바꿀 수 있다.

Ollama Cloud 는 2026-08-27 에 더했다. 그 전의 단일 제공자 규칙을 대체한 것이 2026-08-24 다.

## 기능이 셋이고 각자 제공자를 고른다

| 기능 | 언제 부르는가 | 설정 |
|---|---|---|
| `selector_generate` | 크롤러를 등록할 때 한 번 | `SELECTOR_GENERATE_PROVIDER` |
| `selector_repair` | 운영자가 AI 수정을 누를 때 | `SELECTOR_REPAIR_PROVIDER` |
| `classify` | 공고 하나마다 | `CLASSIFY_PROVIDER` |

셀렉터 생성은 등록할 때 한 번이고 분류는 공고마다 한 번이라 성격이 다르다. 싼 제공자를 분류에
두고 정확한 제공자를 생성에 두는 선택이 가능해야 한다.

## 키는 제공자마다, 모델은 기능마다

2026-08-27 결정이다. 모델을 제공자에 붙이면 같은 제공자를 쓰는 두 기능이 다른 모델을 쓸 수
없다. 셀렉터 생성에 비싼 모델을, 분류에 싼 모델을 두면서 키는 하나만 넣는 쓰임이 이 모양이라야
된다.

값은 `app_settings` 표에 들어간다. 새 표를 만들지 않는다 (`app/llm/settings.py`).

읽기는 환경변수로 떨어진다. 저장된 값이 없으면 배포가 넣어 둔 값을 쓰고, 한 번 저장된 뒤로는
DB 가 이긴다.

화면에 키 전체 값이 나가지 않는다. 끝 네 자리만 보이고, 네 자리 이하는 전부 가린다
(`mask()`).

## 분기하는 코드는 항목 안에만 있다

`app/llm/providers.py` 는 이름 하나를 항목 하나로 바꾸는 일만 한다. 여기가 얇아야 "제공자로
분기하는 코드는 항목 안에만 있다" 가 참이 된다.

`app/llm/base.py` 에는 제공자와 무관한 것만 둔다. 호출이 실패한 방식(`LlmCallError`), 호출
1회의 비용(`Usage`), 항목이 무엇을 적어야 하는지(`Provider`) 셋뿐이다.

`app/llm/gemini.py` 하나였을 때는 오류 타입도 비용 구조체도 거기 있는 것이 자연스러웠다.
제공자가 다섯이 되면 그것이 문제가 된다 — 제공자 하나의 파일이 나머지 넷의 부모 노릇을 하게
된다.

## 조용히 다른 제공자로 넘어가지 않는다

키가 없는 제공자는 그 기능만 실패하고 사유를 말한다. 다른 제공자로 대체하지 않는다.

조용히 넘어가면 비용 기록이 거짓말이 되고, 크레딧이 떨어진 것을 아무도 모르는 채로 다른
계정에서 돈이 나간다.

| reason | 언제 |
|---|---|
| `unknown_provider` | 설정에 적힌 이름이 다섯 중에 없다 |
| `no_schema_support` | 이 기능이 요구하는 스키마 강제를 그 조합이 못 한다 |

## 스키마를 강제하지 못하면 분류에 쓸 수 없다

`NEEDS_SCHEMA` 에 있는 기능은 `classify` 하나다. 분류의 판정 칸이 닫힌 목록인 것이 여기
걸려 있다 (`.claude/docs/classification.md`).

셀렉터 생성은 여기 없다. 스키마를 벗어난 응답이 와도 `parse_selectors()` 가 거절하고 한 번 더
물어보는 길이 있어서다. 분류에는 그 길이 없다 — 목록에 없는 값이 와도 그럴듯해 보이고, 그대로
`normalized_jobs` 에 앉는다.

판정은 제공자가 아니라 제공자와 모델의 조합으로 한다(`forces_schema(model)`). 넷은 어느
모델을 쓰든 강제하지만 Qwen 은 일부 모델에서만 강제하기 때문이다.

| 제공자 | 강제하는가 |
|---|---|
| `gemini` `claude` `gpt` | 모든 모델 |
| `qwen` | `QWEN_SCHEMA_MODELS` 로 시작하는 모델만. 별칭(`qwen-turbo` 등)은 안 된다 |
| `ollama` | 어느 모델도 안 된다. 클라우드가 구조화 출력을 지원하지 않는다 |

Ollama Cloud 는 셀렉터 생성과 AI 수정에는 쓸 수 있고 분류에서는 `no_schema_support` 로
거절된다. 프롬프트로 우회하지 않는다.

GPT 는 `schema_models` 를 두지 않는다. Structured Outputs 가 모델이 아니라 API 에 붙은
기능이기 때문이다. 다만 지원 표가 `gpt-4o-2024-08-06` 과 그 이후까지만 적으므로, 그보다
오래된 모델을 설정에 넣으면 이 가정이 깨진다.

## 호출은 전부 기록한다

`llm_calls` 에 호출 하나가 한 줄이다 (`app/llm/log.py`,
`migrations/0013_llm_calls.sql`).

남기는 것은 제공자, 모델 ID, 무엇을 위한 호출인지, 입출력 토큰 수, 지연, 성공 여부다.

남기지 않는 것은 프롬프트와 응답 본문이다. 비용을 세는 표에 사이트 본문이 한 벌 더 생길
이유가 없다.

기록 실패가 호출을 실패로 만들지 않는다. 표가 없거나 DB 가 잠겨 있어도 분류는 계속 가야
한다 — 남기지 못한 것은 숫자 한 줄이고, 멈추면 사라지는 것은 그 공고의 분류다. 못 남긴
사실은 경고 로그로 남는다.

v1 은 셀렉터 생성 한 번이 전부였다. v2 가 공고마다 분류 호출을 더해서 호출 수가 수집량에
비례한다. 이 숫자가 없으면 비용 질문에 답할 수 없다.

기능별 누적은 `by_feature()` 가 낸다. 호출이 한 번도 없는 기능도 0으로 나온다 — 그래프에서
아예 빠지면 그 기능이 있는지도 알 수 없다.

## 모델 ID 는 코드에 없다

설정에 있다. 모델 ID, 가격, 파라미터 모양은 바뀌므로 외워서 쓰지 않고, 호출을 쓰거나 고칠
때 그 제공자의 현재 문서를 확인한다.

지금 그 제공자가 주는 모델 목록은 화면에서 받아 볼 수 있다(`list_models()`). 받지 못하면
사유가 같이 온다.

API 키는 환경변수와 `app_settings` 에서만 온다. 소스 파일, 템플릿, 로그 줄, 커밋된 `.env`
어디에도 남지 않는다.
