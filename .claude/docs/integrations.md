# 우리 서비스로 나가는 요청

알림(`app/notify/`)과 로고 저장소(`app/storage/`), 그리고 아직 자리만 있는
전달(`app/deliver/`)에 관한 문서다.

## 왜 이 셋이 한 문서인가

셋 다 크롤링 대상이 아니라 우리가 운영하는 곳으로 나가는 요청이다. 물어볼 robots 가 없고,
지킬 호스트 예산이 없고, 딜레이는 아무도 보호하지 않으면서 실행이 끝나는 시각만 민다.

그래서 이 셋만 공용 fetch 클라이언트를 지나지 않는다. 지금 실제로 나가는 것은 앞의 둘이고
그것이 규칙에 적힌 전체 목록이다 (`.claude/rules/crawling.md`).

`app/deliver/` 가 전송을 구현하면 세 번째가 된다. 그때 규칙 파일을 같은 커밋에서 고친다
(`.claude/docs/spring-delivery.md`).

## 알림

새 공고가 적재되면 ntfy 로 한 번 보낸다. 부르는 자리는 크롤 실행의 끝이다
(`.claude/docs/crawl-run.md`).

알림이 오는 이유는 하나뿐이다. 건너뜀도 실패도 알리지 않는다 — 실패는 워크플로우 화면의 실패
배지와 `crawl_runs` 가 이미 들고 있고, 그것을 휴대폰으로 한 번 더 보내면 정작 새 공고 알림이
묻힌다.

한 실행에 알림 하나다. 공고마다 보내지 않는다. SK 는 한 번에 104건이 들어오고, 그러면 알림이
104개 온다.

같은 이유로 본문에 104건을 다 넣지 않는다. 앞의 몇 건만 보이고 나머지는 `외 N건` 으로 줄인다.
다 넣은 알림은 읽히지 않고, 읽히지 않는 알림은 안 보낸 것과 같다.

본문은 마크다운이다. 상태를 한눈에 보이게 하는 것은 문장이 아니라 ntfy 태그 쪽이다.

여기서 예외가 나가지 않는다. 설정을 읽지 못하든 알림 서버가 죽어 있든 로그 한 줄로 끝내고
실행 결과는 그대로 둔다. 알림이 안 갔다고 수집이 실패한 것은 아니다.

보내기 전에 주소·토픽·우선순위를 한 번 본다. 틀린 설정은 5초를 기다린 뒤가 아니라 지금
알린다(`TIMEOUT_SECONDS = 5.0`).

## 로고 저장소

`companies` 의 로고 파일을 S3 호환 엔드포인트에 넣고 공개 주소로 읽는다.

2026-08-28 에 예외로 들인 두 번째 컨테이너다. SQLite 는 파일 하나라 업로드된 이미지를 담을
수 없고, MinIO 는 S3 API 를 말하므로 나중에 실제 S3 로 바꾸는 것이 엔드포인트 설정 하나다
(`.claude/rules/core.md`).

받는 것은 이미지뿐이고 크기 상한이 있다. 어느 형식인지는 파일 이름이 아니라 앞 몇 바이트로
정한다 — PNG, JPEG, WebP 셋 중 하나가 아니면 거절한다(`MAX_IMAGE_LABEL = "2MB"`).

주소 형식을 우리가 만들지 않는다. `endpoint_url` 이 있으면 `엔드포인트/버킷/키` 로, 비어
있으면 SDK 가 지역으로 `버킷.s3.지역.amazonaws.com/키` 를 만든다. 운영자가 고를 값이 아니다.

연결 확인은 작은 객체를 넣고, 읽고, 지운다(`check()`). 실패하면 어느 걸음에서인지가 같이
온다.

엔드포인트가 운영자 설정이라 우리가 배포하지 않은 버킷을 가리킬 수도 있다. 그래도 크롤링
대상은 아니다 — 이 모듈은 자기가 넣은 객체만 읽고 쓴다. 그것이 경계선이고, 자기가 올리지
않은 것을 가져오는 모듈은 이름이 무엇이든 크롤러다.

## 전달

`app/deliver/` 에는 설정만 있고 전송 코드가 없다. 오공고 백엔드가 받는 주소와 인증 헤더를
어드민에서 정해 두는 자리다.

무엇을 어떤 모양으로 보낼지는 `.claude/docs/spring-delivery.md` 가 정한다. 아직 합의가 남은
항목이 있어 구현 전이다.

`auth_header` 는 값을 넣어 둘 자리일 뿐이고, 소비 측에 자격증명을 어떻게 줄지는 정하지 않았다
(`.claude/docs/api-contract.md`).

## 설정은 셋 다 같은 방식이다

값은 `app_settings` 표에 들어간다. 새 표를 만들지 않는다.

`app/settings.py` 와 같은 표를 쓰지만 저장소를 따로 둔다. 그쪽은 정수 하나를 다루고
`/api/settings` 가 `dict[str, int]` 로 내보내는데, 여기 값은 켜기·끄기와 주소와 낱말이 섞여
있다. 그 API 의 응답 모양을 알림 때문에 바꾸면 이미 있는 화면이 같이 흔들린다.

환경변수 짝을 두지 않는다. 동시 실행 상한과 달리 배포가 정할 값이 아니라 운영자가 화면에서
정하는 값이고, 짝을 만들면 같은 설정이 두 곳에 생긴다.

읽기는 예외를 던지지 않는다. 읽는 자리가 크롤링 실행의 끝이거나 화면이라, 손으로 넣은 깨진
값 하나가 수집을 멈추거나 화면을 못 열게 둘 수 없다. 읽지 못한 값은 기본값으로 떨어지고
로그에 남는다.

쓰기는 반대로 깐깐하다. 저장되는 값은 전부 검증을 지나고, 하나라도 걸리면 아무것도 저장되지
않는다.

## 화면

| 설정 | 화면 라우터 |
|---|---|
| 알림 | `app/api/ui_notify.py` |
| 저장소 | `app/api/ui_storage.py` |
| 전달 | `app/api/ui_deliver.py` |

`deliver_auth_header` 는 화면이 값을 그대로 그린다
(`app/templates/fragments/deliver_form.html:40` 의 `type="text"`). 저장소와 제공자 키는
마스킹하고 있어서 여기만 다르다. 전송을 구현할 때 같이 고친다.
