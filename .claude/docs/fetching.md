# 수집 경로와 fetch 규율

페이지 하나를 가져오는 일에 관한 문서다. 무엇으로 가져올지 고르는 것
(`app/crawler/collect.py`)과, 어떻게 나가는지 정하는 것(`app/crawler/fetcher.py`)이 갈려 있다.

제약 자체는 `.claude/rules/crawling.md` 에 있다. 여기서는 그 제약이 코드에서 어떤 모양인지를
적는다.

## 밖으로 나가는 요청은 한 곳을 지난다

`app/crawler/fetcher.py` 의 `Fetcher` 하나가 크롤링 대상으로 나가는 유일한 경로다.
셀렉터 생성이 페이지를 가져올 때도, 등록할 때 알아낸 API 를 다시 불러 확인할 때도 여기를
지난다.

호출부는 `get_fetcher()` 로 공용 인스턴스를 받는다. 호스트별 딜레이는 인스턴스가 하나일 때만
사실이다 — 각자 만들어 쓰면 레포에 적힌 어떤 rate limit 도 참이 아니게 된다.

이 클라이언트가 실제로 하는 일은 넷이다.

| 무엇 | 어떻게 |
|---|---|
| 신원 | `CRAWL_USER_AGENT` 를 그대로 보낸다. 브라우저 위장은 하지 않는다 |
| 예의 | 같은 호스트로 가는 요청 사이에 `CRAWL_DELAY_SECONDS`(기본 3초)를 실제로 기다린다 |
| robots | 첫 요청 전에 `robots.txt` 를 확인하고, disallow 면 대상 URL 로 요청을 보내지 않는다 |
| 재시도 | transport 실패만 `CRAWL_MAX_RETRIES`(기본 3) 만큼 백오프 재시도한다 |

4xx 는 재시도하지 않는다. 4초 뒤에 다시 물어도 같은 답이 온다.

리다이렉트는 따라가지만, 리다이렉트로 다른 호스트에 도착한 경우의 robots 재확인은 하지 않는다.
지금 그것이 필요한 사이트가 없다.

실패는 타입으로 갈려 올라온다. 이 구분이 `crawl_runs.error_class` 로 이어진다
(`.claude/docs/crawl-run.md`).

| 예외 | 언제 |
|---|---|
| `TransportError` | 타임아웃, 연결 끊김, 5xx. 재시도를 다 쓰고도 실패한 것만 |
| `ResponseStatusError` | 4xx |
| `RobotsDisallowedError` | robots 가 막은 경로. 대상 URL 로는 요청이 나가지 않았다 |

## 예외는 둘뿐이다

우리가 운영하는 서비스로 나가는 요청은 이 클라이언트를 지나지 않는다. 물어볼 robots 가 없고,
지킬 호스트 예산이 없고, 딜레이는 아무도 보호하지 않으면서 실행이 끝나는 시각만 민다.

`app/notify/` 와 `app/storage/` 가 그 둘이고, 그것이 전체 목록이다
(`.claude/docs/integrations.md`).

`app/deliver/` 가 실제로 전송을 구현하면 세 번째가 된다. 그때 규칙 파일을 같은 커밋에서
고친다 (`.claude/docs/spring-delivery.md`).

## 무엇으로 가져올지는 목록과 상세가 따로 정해진다

`crawlers.list_mode` 와 `crawlers.detail_mode` 가 각각 `static` / `api` / `playwright` 중
하나다. 섞어 쓰는 것이 정상적인 선택지다 — 목록이 JSON API 로 오고 상세는 서버가 그려 주는
문서인 사이트가 있다.

| 모드 | 목록 | 상세 |
|---|---|---|
| `static` | `httpx` 로 받은 HTML 에 목록 셀렉터를 적용 | 항목의 링크를 그대로 따라간다 |
| `api` | `api_config_json` 이 가리키는 엔드포인트의 JSON | 공고 id 로 한 건을 지목해 가져온다 |
| `playwright` | 브라우저로 렌더한 HTML | 브라우저로 렌더한 HTML |

`api` 가 부를 엔드포인트와 응답에서 읽을 자리는 `crawlers.api_config_json` 에 있고, 형식은
`app/selector/api_schema.py` 가 강제한다. 목록과 상세가 둘 다 `api` 인 크롤러는 셀렉터를
하나도 쓰지 않아서, 빈 셀렉터로도 실행된다.

`app/crawler/collect.py` 의 `open_collectors()` 가 이 실행이 쓸 수집기 둘을 만들고 브라우저
수명을 들고 있다. 브라우저는 실제로 필요한 쪽에서만 뜬다 — 목록이 `api` 면 목록 때문에 뜨지
않고, 양쪽이 다 `playwright` 면 하나를 나눠 쓴다. 인스턴스 하나가 150~300MB 다.

모드는 등록할 때 정해지고 운영자가 크롤러 화면에서 바꾼다
(`PUT /api/crawlers/{crawler_id}/collect-modes`). 바꾼 값을 자동 판정이 덮어쓰지 않는다.

화면에는 낱말로 적는다 (`app/api/ui.py` 의 `describe_path()`).

| 무엇 | 낱말 |
|---|---|
| 목록을 얻는 법 | `목록 API` / `목록 렌더` / `정적 목록` |
| 상세로 가는 법 | `상세 API` / `링크` / `항목 속성` |

## 2026-08-25 측정으로는 브라우저가 필요한 사이트가 없다

여섯 사이트 전부 목록과 상세를 `httpx` 로 받는다. 그중 넷은 JSON 또는 HTML 조각 API 다.
`playwright` 는 사이트별 측정에 근거한 선택이지 기본값이 아니다
(`.claude/site-recipes/`, `.claude/docs/ocr-benchmark.md`).

## 0개 매칭이 두 가지 원인을 가진다

셀렉터가 아무것도 못 잡았을 때 원인은 둘 중 하나다. 사이트가 마크업을 바꿨거나, 목록을 JS 가
그려서 정적 HTML 에는 애초에 없거나. 앞은 셀렉터 재작성이고 뒤는 렌더 모드 승격이라, 사유에
어느 쪽인지가 없으면 운영자가 매번 페이지를 직접 열어 봐야 한다.

`app/crawler/shell.py` 가 정적 HTML 이 껍데기인지 본다. `script`·`style`·`nav`·`header`·
`footer` 를 걷어낸 뒤의 본문 길이와 반복 항목 수를 세고, `seeds/sample-sites.json` 의 실측을
경계로 쓴다 — 목록이 있는 쪽의 최소가 816자·4항목, 없는 쪽의 최대가 608자·0항목이라 경계를
그 사이에 뒀다 (`SHELL_TEXT_LIMIT = 700`, `LIST_MIN_REPEATS = 3`).

판정은 사유 한 줄을 더 적는 것으로 끝난다. 승격은 운영자가 정한다.

## 마감이 지난 공고는 상세를 열지 않는다

목록에서 읽은 날짜가 오늘보다 이전이면 그 공고의 상세 요청을 보내지 않는다
(`app/crawler/deadline.py`). 실패가 아니라 `skipped_count` 다.

수집은 날짜 형식을 새로 알지 않는다. 어떤 표기를 날짜로 읽을지는 정규화 규칙
(`app/normalize/rules.py` 의 `date_parse`)이 이미 알고 있고, 여기서는 그 규칙을 그대로 태워
나온 값만 본다. 같은 사이트의 같은 값이 화면과 수집에서 다르게 읽히면 안 된다.

판정은 한쪽으로만 기운다. 지났다고 확실히 읽은 것만 마감이고 나머지는 전부 진행 중이다.

| 목록에서 읽은 값 | 판정 |
|---|---|
| 오늘보다 이전 날짜 | 마감 |
| 오늘 | 진행 중 |
| 오늘보다 뒤 날짜 | 진행 중 |
| 빈 값 (상시채용) | 진행 중 |
| 규칙이 날짜로 읽지 못한 값 | 진행 중 |

날짜 형식이 바뀐 사이트를 조용히 전부 버리는 것이 이 기능의 유일한 위험이다. 못 읽은 것을
지난 것으로 취급하면 그 사이트의 공고가 한 건도 들어오지 않는데, 실행은 실패로 남지도 않는다.

비교는 `DISPLAY_TIMEZONE` 의 오늘로 한다. 마감일은 시각이 아니라 날짜라, UTC 의 오늘과
비교하면 한국 시각 오전 아홉 시간 동안 하루 일찍 마감된 것으로 보인다.

목록에서 읽은 날짜를 마감일로 볼 수 있는 크롤러인지는 수집기가 들고 있다
(`list_date_is_deadline()`). 항목마다 다시 볼 값이 아니라 그 크롤러의 설정이다.

## 쪽 넘기는 목록은 아는 공고를 만나면 멈춘다

목록 API 가 쪽을 넘기는 사이트에서, 그 쪽이 전부 이미 아는 공고면 거기서 멈춘다. 목록이
새것부터 오므로 그 뒤는 더 옛것이다 (`app/crawler/api_source.py`).

판정은 러너가 넘긴 `known` 콜백이 한다 — `raw_jobs` 에 그 `source_url` 이 있는가다.
